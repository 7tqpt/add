# لوحة تحكم تطبيق الجوال

لوحة إدارة ويب عربية (RTL) لإدارة تطبيق جوال: الإحصائيات، المستخدمون، البلاغات، الإشعارات،
إصدارات التطبيق، سجل العمليات، وإعدادات التشغيل.

مبنية بـ **React 19 + Vite + TypeScript + Tailwind CSS 4**، وتتصل بـ **Supabase** للمصادقة
وقاعدة البيانات.

## التشغيل السريع

```bash
npm install
npm run dev
```

ثم افتح <http://localhost:5173>.

بدون إعداد Supabase تعمل اللوحة في **وضع العرض التجريبي**: بيانات ثابتة مولّدة من بذرة واحدة،
وتسجيل الدخول يقبل أي بريد إلكتروني مع كلمة مرور من ٤ أحرف فأكثر. هذا يتيح تصفّح كل الشاشات
قبل وجود أي خادم.

## الربط بـ Supabase

1. أنشئ مشروعاً على [supabase.com](https://supabase.com).
2. شغّل محتوى `supabase/schema.sql` في **SQL Editor** — ينشئ الجداول وسياسات RLS.
3. (اختياري) شغّل `supabase/seed.sql` لتعبئة بيانات تجريبية بدل الشاشات الفارغة.
4. أنشئ مستخدماً من **Authentication ← Users**، ثم امنحه دور المالك:

   ```sql
   insert into public.admins (user_id, email, role)
   select id, email, 'owner' from auth.users where email = 'you@example.com';
   ```

5. انسخ `.env.example` إلى `.env` واملأ المفتاحين:

   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJ...
   ```

6. أعد تشغيل خادم التطوير. ستتحوّل كل الشاشات تلقائياً إلى البيانات الحقيقية.

> المفتاح المستخدم هو `anon key` العلني، والحماية الفعلية في سياسات RLS: كل الجداول مقفلة
> ولا يصل إليها إلا من كان له صف في جدول `admins`.

## الشاشات

| الشاشة | المسار | المحتوى |
| --- | --- | --- |
| لوحة المعلومات | `/` | مؤشرات الأداء، التثبيتات اليومية حسب المنصة، الجلسات، توزيع المنصات، أعلى الدول |
| المستخدمون | `/users` | بحث وتصفية وترقيم، إيقاف/تفعيل الحسابات، تصدير CSV |
| تفاصيل المستخدم | `/users/:id` | الملف الشخصي، سجل الجلسات، الأجهزة المسجّلة، المشتريات |
| البلاغات والدعم | `/tickets` | قائمة البلاغات، تغيير الحالة والأولوية، المحادثة والرد على المستخدم |
| الإشعارات | `/notifications` | إنشاء إشعار (فوري أو مجدول) + سجل الإرسال ونسب الفتح |
| إصدارات التطبيق | `/versions` | نسبة الطرح التدريجي والتحديث الإجباري لكل منصة |
| سجل العمليات | `/audit` | كل تعديل قام به المسؤولون: من، ماذا، متى |
| الإعدادات | `/settings` | وضع الصيانة، السماح بالتسجيل، أدنى إصدار مدعوم، إدارة المسؤولين |

## الأدوار والصلاحيات

ثلاثة أدوار، مطبّقة في سياسات RLS أولاً وتعكسها الواجهة ثانياً:

| الدور | الصلاحيات |
| --- | --- |
| `owner` | كل شيء، بما فيه إضافة المسؤولين وتغيير أدوارهم |
| `admin` | تعديل كل البيانات، دون إدارة المسؤولين |
| `viewer` | قراءة فقط — كل أزرار التعديل معطّلة |

في وضع العرض التجريبي يمكنك تبديل دورك من **الإعدادات ← المسؤولون والصلاحيات** لمعاينة أثر
كل دور على الواجهة.

## سجل العمليات

كل تعديل (إيقاف مستخدم، إرسال إشعار، تغيير إعداد، الرد على بلاغ…) يُسجَّل تلقائياً من طبقة
الخدمات، لا من الشاشات — فلا يمكن لشاشة جديدة أن تنسى التسجيل. الجدول **للإلحاق فقط**: سياسات
RLS تسمح بالإضافة والقراءة، ولا توجد سياسة تعديل أو حذف إطلاقاً، حتى لا يمحو مسؤول أثر ما فعله.

## البنية

```
src/
├─ components/
│  ├─ charts/      رسوم SVG مكتوبة يدوياً (بدون مكتبة رسوم)
│  ├─ layout/      الشريط الجانبي والعلوي والهيكل العام
│  └─ ui/          البطاقات، الأزرار، الحقول، الشارات، التأكيد، الترقيم، التصدير
├─ context/        المصادقة والأدوار والوضع الليلي
├─ data/mock.ts    بيانات العرض التجريبي (بذرة ثابتة)
├─ hooks/
├─ lib/            عميل Supabase، الأنواع، تنسيق الأرقام والتواريخ، تصدير CSV
├─ pages/
└─ services/       طبقة البيانات — Supabase أو البيانات التجريبية
```

كل شاشة تمرّ عبر `src/services/*`، وكل خدمة تختار مصدرها حسب `isSupabaseConfigured`. إضافة
جدول جديد تعني إضافة خدمة واحدة، لا تعديل الشاشات.

## ملاحظات التصميم

- **RTL أصيل**: خصائص CSS المنطقية (`start`/`end`) في كل مكان، والمحور الزمني في الرسوم يسير
  من اليمين (الأقدم) إلى اليسار (الأحدث) ليطابق اتجاه القراءة.
- **ألوان مُتحقَّق منها**: لوحة الألوان الفئوية اجتازت فحوصات عمى الألوان والتباين في الوضعين
  النهاري والليلي، بترتيب ثابت للألوان لا يتغيّر مع تغيّر البيانات.
- **كل رسم له مقابل جدولي**: زر تبديل بين «رسم» و«جدول» في كل بطاقة رسم، حتى لا تكون القيمة
  محجوبة خلف التمرير بالفأرة.
- **الوضع الليلي** درجات مختارة للخلفية الداكنة، وليس انعكاساً آلياً للوضع النهاري.
- **التصدير** ملفات CSV تبدأ بـ BOM حتى يقرأها Excel كـ UTF-8 وتظهر العربية سليمة. التصدير
  يشمل كامل النتائج المصفّاة، لا الصفحة الظاهرة فقط.

## الأوامر

| الأمر | الوظيفة |
| --- | --- |
| `npm run dev` | خادم التطوير |
| `npm run build` | فحص الأنواع + بناء للإنتاج في `dist/` |
| `npm run preview` | معاينة نسخة الإنتاج محلياً |
| `npm run typecheck` | فحص الأنواع فقط |

يعمل `npm run build` تلقائياً على كل دفعة و pull request عبر GitHub Actions
(`.github/workflows/ci.yml`).
